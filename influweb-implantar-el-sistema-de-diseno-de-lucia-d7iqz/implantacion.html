Implantación del sistema de diseño en influweb.es

Capa visual de Lucía aplicada sobre la web en producción, sin rediseñar ni tocar contenido. Este documento es el registro de ejecución y el manual de reversión. No se publica en producción hasta el visto bueno de Rafael.

Estado: capa construida y validada en local (muestra index.html). El enqueue en WordPress se aplica en la web real y se prueba con la checklist de abajo; las capturas se adjuntan en la tarea con los nombres indicados.

1. Archivos de la entrega

2. Pasos ejecutados en el tema

Todo va en un único archivo de tema (hijo o snippet propia) y se activa/desactiva desde un solo punto.

2.1 Enqueue solo en el frontend

<?php
/**
 * INFLUWEB · capa visual (sistema de diseño)
 * Archivo: assets/css/tokens.css y assets/css/influweb-web.css dentro del tema.
 */
add_action( 'wp_enqueue_scripts', function () {
    if ( is_admin() || wp_doing_ajax() || is_customize_preview() && false ) {
        return; // nunca en admin
    }
    $dir = get_stylesheet_directory();
    $uri = get_stylesheet_directory_uri();

    wp_enqueue_style(
        'iw-tokens',
        $uri . '/assets/css/tokens.css',
        [],
        filemtime( $dir . '/assets/css/tokens.css' )
    );
    wp_enqueue_style(
        'iw-web',
        $uri . '/assets/css/influweb-web.css',
        [ 'iw-tokens' ],                              // tokens primero
        filemtime( $dir . '/assets/css/influweb-web.css' )
    );
}, 20 );

2.2 Clase iw-scope al body

add_filter( 'body_class', function ( $classes ) {
    if ( ! is_admin() ) {
        $classes[] = 'iw-scope';
    }
    return $classes;
} );

Requiere que header.php use <body <?php body_class(); ?>>. Si el tema no lo usa, se añade esa llamada (una línea) y se revisa el resto de clases del tema para no romper estilos existentes.

2.3 Logo PNG → SVG

Se sustituye el PNG del logo por logo-influweb.svg manteniendo texto y orden. Dos caminos, en este orden de preferencia:

  1. Por el Personalizador/Apariencia del tema: subir el SVG y guardar. Un paso, 100 % reversible.
  2. Si el tema lleva el logo en la plantilla: filtrar el HTML del logo con la misma ruta del SVG, sin tocar el alt.

El SVG necesita estar permitido en medios (si el sitio restringe SVG, se sube por FTP a assets/img/ y se referencia por ruta).

6. Reversión en un paso

La capa completa se apaga comentando una sola línea: la del add_action( 'wp_enqueue_scripts', ... ). Con eso desaparecen los dos CSS. La clase del body es inocua sin CSS, pero para dejarlo impecable se comenta también el filtro body_class (segunda línea) y el logo vuelve desde el Personalizador en 10 segundos.

// REVERSIÓN RÁPIDA (menos de 1 minuto)
// 1) Comentar el add_action de wp_enqueue_scripts  ->  la web vuelve a su aspecto anterior
// add_action( 'wp_enqueue_scripts', 'iw_enqueue_capa_visual', 20 );

// 2) Opcional, para dejarlo limpio del todo:
// add_filter( 'body_class', 'iw_body_class_scope' );

// 3) Logo: Apariencia > Personalizar > Identidad > volver a subir el PNG anterior.
// 4) Purgar caché (plugin de caché + CDN) y comprobar en incógnito.

Prueba de reversión: se ejecuta en staging antes de tocar producción; se valida que la home se ve exactamente como el "antes" (reversion-despues.png idéntico a antes-*.png), sin errores 404 de hojas de estilo en consola y con el logo PNG de vuelta. Se documenta el tiempo real de la operación.

7. influweb.es vs influweb.ai

Pendiente de confirmar en los dos paneles (Apariencia → Temas): si no comparten tema, esta capa hay que repetirla en el segundo dominio.

  • influweb.es: WordPress con tema propio/clásico → aplica esta guía.
  • influweb.ai: comparte textos y orden de secciones, pero su estructura de entrega apunta a otra plataforma de sitio (no a un tema de WordPress). Antes de replicar nada hay que verificar generador del sitio y acceso al panel.

Si influweb.ai no es WordPress, el enqueue no existe: se portan los tokens.css al constructor que use (variables y clases) y se documenta aparte. No se asume nada sin verlo en el panel.

9. Criterio de aceptación

  • La web real se ve como index.html: mismos bloques, mismos textos, misma jerarquía, con la paleta y tipografía del sistema.
  • Cero elementos rotos: sin scroll horizontal en 360/390/768/1024/1440 px, sin solapes del header sticky, sin campos desalineados.
  • Admin y plugins sin cambios visuales.
  • Reversión probada en un paso, con evidencia.
